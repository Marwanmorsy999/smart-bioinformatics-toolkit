Real NCBI BLASTN · browser-only control flow

16S rRNA identification

Validate your FASTA, approve an exact plan, then submit to NCBI through the existing single-use consent gate. Every scientific value below comes from a result actually retrieved by the platform. Nothing on this page is simulated unless the operator has explicitly enabled mock mode — and then it is labelled as synthetic.

Research use only. Similarity is evidence, not proof of species identity or a clinical diagnosis. Results require independent interpretation. Research-use terms.
Data handling. Browser validation is local. When you create a request, your FASTA is sent to Smart Bioinformatics AI and stored in D1 for that request. It is not sent to NCBI until you review and approve the plan and explicitly submit using the single-use consent. FASTA bytes are stored inline in D1 for this request, not durably in object storage; no retention period or deletion mechanism is documented. Do not submit sequences you are not authorised to transmit.
Technical data-flow details
  • What is sent to this platform: your FASTA text plus a short question/objective, sent to POST /api/ai/requests. Validation, statistics and previews before that step run in your browser; nothing else leaves your browser for those local checks.
  • What is stored: FASTA bytes are stored inline in D1 datasets.fasta_text; a SHA-256 hash, size, filename, provenance/status and any retrieved result table; plus request, plan and job rows, a single-use consent record, and append-only audit events. Audit events contain no sequence. Nothing is stored in durable object storage; no durable R2 byte storage. No retention period and no user-facing deletion mechanism is documented.
  • What goes to NCBI: only the approved FASTA plus the approved parameters DATABASE=rRNA_typestrains/16S_ribosomal_RNA and PROGRAM=blastn (CMD=Put); nothing unrelated, no project files, no secrets, and no consent token. Status and results polling (CMD=Get) sends only the RID. The outgoing NCBI URL is never logged, and the consent token is never sent to NCBI. Nothing is sent to any other external service.
  • When external transmission occurs: nothing is sent to NCBI before approval and submission. External transmission to NCBI occurs only after you review and approve the plan and explicitly submit using the single-use consent. Nothing else is sent to external services.
  • What consent authorizes: a short-lived, single-use token bound to this exact input hash, database and program authorizes exactly one external submission; it is not reusable.

  3. 3

    Submit and follow the real RID

    One submission per 10 seconds is permitted by NCBI usage rules.

    Status is checked at most once per minute (the server enforces this too). Checking does not fetch results until the job is complete. No result is shown unless a real tabular report is retrieved and validated.

    NCBI may occasionally return inconsistent status information. When this happens, monitoring stops and the request is held for verification. No scientific result is shown until the platform retrieves and validates a real results file.

    Technical detail

    The API reports a terminal status_conflict state when structured status evidence disagrees; it is never shown as queued, no-hit or success, and monitoring stops. Production checks only NCBI's canonical status for your RID; no result is shown until a real results file is retrieved.
