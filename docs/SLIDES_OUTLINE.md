### Slide 1 — Title and thesis

- Title: **Smart Bioinformatics Toolkit — conservative 16S verdicts and a reproducible benchmark**.
- Subtitle: *Research and education use only. Not a clinical diagnostic device.*
- Message: turn raw BLAST similarity evidence into an explained, conservative verdict, and
  measure the trade-off against baselines on real data.
- Numbers: none. External claims: none.

### Slide 2 — The problem

- A plain top hit names a species even when the true species is absent from the reference
  database; a fixed 98.65% identity cutoff still lets a close sibling clear it.
- Users need an explicit "insufficient evidence" outcome and an auditable comparison.
- Number: `98.65%` — from `benchmark_data/RESULTS.md` (cutoff method label).
- External claims: 16S can be unresolved at species level [E-CEREUS, UNVERIFIED]; the
  reference data are bacterial 16S RefSeq targeted loci [E-REFSEQ]; the database name is
  `16S_ribosomal_RNA` [E-DBNAME].

### Slide 3 — What the toolkit does

- Independent stages: local FASTA validation/statistics → BLAST tabular analyzer → taxonomy
  consensus → verdict layer → printable report with CSV/JSON exports.
- Two matching interfaces: browser (vanilla JS ES modules) and Python CLI.
- A reproducible benchmark generator and evaluator compare three methods.
- Numbers: none. External claims: NCBI BLAST URL API parameters and limits [E-BLASTAPI];
  16S database name [E-DBNAME].

### Slide 4 — Verified benchmark setup and provenance

All values on this slide are from `benchmark_data/RESULTS.md`:

- Generated 2026-11-24; BLAST `blastn: 2.17.0+`.
- Reference: `bacteria.16SrRNA.fna.gz`; taxonomy dump `nodes.dmp` + `names.dmp` (no
  `rankedlineage.dmp` in this release); accession-to-taxid extracted from
  `bacteria.16SrRNA.gbff.gz`, 26,888 rows.
- Conditions: held-out and noisy, n=200 per seed, length=500 nt, substitution rate=0.005,
  seeds 1, 2, 3. Saved outputs and exact commands are in `benchmark_data/`.
- External claim: bacterial 16S RefSeq targeted-loci data [E-REFSEQ].

### Slide 5 — Held-out headline result

All values from `benchmark_data/RESULTS.md` (held-out; n=200 per seed, 500 nt, 0.005;
seeds 1, 2, 3):

| Method | Calls/200 (mean) | Wrong calls (mean) | Wrong rate among calls | Abstentions (mean) |
| --- | --- | --- | --- | --- |
| Plain top hit | 200.0 | 143.3 | 0.717 | 0.0 |
| Top hit + 98.65% cutoff | 87.7 | 38.0 | 0.431 | 112.3 |
| Toolkit verdict | 49.7 | 12.7 | 0.257 | 150.3 |

- Per-seed wrong calls (top / cutoff / verdict): seed 1: 142 / 45 / 13; seed 2: 133 / 25 /
  10; seed 3: 155 / 44 / 15.
- Wilson 95% CI on correct-call rate (seed 1): top [0.2315, 0.3564], cutoff [0.4374, 0.6321],
  verdict [0.6113, 0.8445].
- Takeaway: fewer confident wrong calls, but species is called far less often. Compare call
  rates together with wrong counts — not "more accurate at naming species" in general.
- External claim: benchmark numbers [E-BENCH, verified].

### Slide 7 — What did NOT work

- **RDP rejected.** Official pages were unreachable (transport error), so terms could not be
  verified; the candidate was rejected as unverifiable. Source: `docs/API_CATALOG.md`
(RDP section).
  External claim [E-RDP, UNVERIFIED].
- **Name drift not implemented.** No valid-name / name-drift flag. The "uncultured"/"sp."/
  "Candidatus" handling is only an uninformative-name filter; LPSN-based lookup was rejected
  (API requires registration; offline design) and `merged.dmp`/`delnodes.dmp` are taxid
  merge/deletion records, not nomenclatural validity. Source: `docs/NAME_DRIFT_NOTES.md`.
  (Internal implementation status; no dedicated EVIDENCE_LEDGER row.)
- **Live NCBI not exercised.** The remote backend and `--online` resolution were tested only
  in MOCK mode and with mocks; no live NCBI request was made. Sources: `docs/CONTRACTS.md`,
  `web-platform/functions/README.md`. (Internal test status; no dedicated ledger row.)
- **Browser TLS blocked.** The paired browser and `curl` both rejected the `pages.dev` TLS
  certificate in this environment, so live rendering was not verified; the Cloudflare API
  confirmed the deployment exists and succeeded. Sources: `docs/LOOP_LOG.md`,
  `docs/PROJECT_SUMMARY.md`. External claim [E-DEPLOY, verified].
- Numbers: none.

### Slide 8 — Architecture

- Mermaid diagram (see `README.md`): browser + Python CLI inputs → BLAST analyzer → taxonomy
  resolver → verdict layer → report; NCBI 16S RefSeq + taxdump → benchmark generator →
  `blastn` → taxonomy/verdict → `benchmark-eval` → generated `RESULTS.md`; browser → Pages
  Functions → D1 → NCBI BLAST URL API.
- Cloudflare Pages serves the static UI; Pages Functions (no framework, no R2, no paid
  services) provide submit/status/results/history backed by D1; MOCK mode disables network
  calls; the D1 `database_id` placeholder must be replaced before deploy. Sources:
  `docs/CONTRACTS.md`, `web-platform/functions/README.md`, `web-platform/wrangler.toml`.
- Numbers: none. External claims: NCBI BLAST URL API [E-BLASTAPI]; 16S database name
  [E-DBNAME].

### Slide 10 — Limitations and takeaways

All quantitative limits from `benchmark_data/RESULTS.md`:

- Truth comes from FASTA headers and can be wrong; one database release; simulated
  substitutions/indels are not real sequencing error or strain variation.
- Queries are the first 500 nt (V1-V3-like start region); held-out removes source accessions
  but the true species may still be represented by other strains; group-level containment of
  truth was 0 in these runs.
- Honest takeaway: the verdict is more conservative, not universally more accurate; report
  call rates alongside wrong counts.
- Research use only. Live preview URL and deploy steps are in `README.md`. Next steps:
  curator review of difficult groups, live NCBI exercise, real-browser check of the live
  deployment.
- External claim: benchmark numbers [E-BENCH, verified].
